# 2026년 자율주행 AI챌린지 — 자율주행 AI 기술 보고서 (1차 파이프라인 검증본)

> **문서 성격 안내**: 본 보고서는 `report_rule.md` 목차 지침을 따르되, 실제로 수행·측정된 결과만을 근거로 작성함. 대회 최종 목표치(충돌률 0% 등)를 가정한 예시가 아니라, **제주(jeju) 단일 사이트 데이터 · GTX 1660(6GB) 1대 · 200,000 스텝**이라는 명시된 조건 하의 1차 검증 실험 결과를 그대로 기술함. 최종 제출 전 한남(hanam) 데이터 통합 및 스텝 수 확장이 필요함을 6장에 명시함.

## 1. 개요 및 최종 목표 (Executive Summary)

- **목표 과제**: 모션 플래닝 (Motion Planning) — Waymax 시뮬레이터 기반 폐루프(Closed-loop) 주행 궤적 생성
- **팀명/모델명**: [팀명 미기재] / V-Max SAC-LQ Planner (Jeju-Only Phase-1)
- **대회 문제 정의**: 인지된 주행 환경(정밀지도 + 주변 동적 객체)에서 충돌·도로이탈 없이 목적지 방향으로 진행하는 미래 주행 궤적을 생성하는 정책(policy) 모델을 학습하고, `ScenarioScore = no_collision × on_road × (7·progress + 3·comfort) / 10` 수식으로 채점됨
- **핵심 접근 전략(Key Differentiators)**:
  1. 베이스라인 V-Max(SAC) 골격을 그대로 채택하되, 리소스 제약형 로컬 GPU(6GB) 환경에 맞춰 `num_envs`, `buffer_size` 등 메모리 연관 하이퍼파라미터를 재조정하여 OOM 없이 안정적으로 완주 가능한 학습 레시피를 확보함
  2. 보상 함수(`reward_config`)를 대회 채점식과 동일 계열인 `offroad_in_box`(방향 무관 도로이탈), `overlap`(충돌), `expert_progression`(진행도) 항으로 구성하여 학습 목적함수와 평가 지표 간 괴리를 최소화함
  3. 데이터 파이프라인(301-step 원본 → 91-step WOMD 포맷 → Waymax 샤드)을 자체 검증하여, 실제 학습·평가·제출물 export까지 엔드투엔드로 1회 완주시킴
- **베이스라인 대비 현재 상태**: 베이스라인 권장 학습량(RTX 4090, 25,000,000 스텝, 약 9시간) 대비 **0.8% 규모(200,000 스텝)** 로 실행한 파이프라인 검증 단계이며, 성능 자체의 최종 비교는 아직 유효하지 않음. 본 보고서의 의의는 "파이프라인이 깨지지 않고 끝까지 동작하며, 학습이 실제로 진행되고 있음"을 정량적으로 증명하는 데 있음

## 2. 시스템 아키텍처 및 연산량 최적화 (System Architecture)

### 2.1 전체 파이프라인

[다이어그램: 원본 TFRecord(301-step, jeju) → make_91f.py(WOMD 91-step 변환) → make_waymax_shards.py(심링크 샤딩, @N) → Waymax simulator_state_generator → V-Max SAC 학습 루프(Actor/Critic) → evaluate.py(폐루프 평가) → export_policy_weights.py(제출용 weights.pkl)]

| 단계 | 입력 | 처리 | 출력 |
|---|---|---|---|
| ① 데이터 변환 | jeju 301-step TFRecord 23,753개 (76GB) | `make_91f.py`: 시나리오당 3개 윈도우(0/100/200 스텝 시작) 절단, 과거10·현재1·미래80 재포맷 | 91-step TFRecord 23,753개 |
| ② 샤딩 | 91-step TFRecord 트리 | `make_waymax_shards.py`: 파일명 정렬 후 심링크, `manifest.csv` 생성 | `train_91f_shards.tfrecord@23753` |
| ③ 학습 | Waymax 샤드 경로 | V-Max SAC 학습 루프 (JAX/XLA, CUDA 13) | `model_final.pkl` 체크포인트 |
| ④ 평가 | 학습 체크포인트 + 샘플 검증셋 | `evaluate.py` 폐루프 롤아웃 | `evaluation_results.txt`, `evaluation_episodes.csv` |
| ⑤ 제출물 변환 | `model_final.pkl` | `export_policy_weights.py` | `weights.pkl` (policy 파라미터만 numpy dict, 68 array) |

### 2.2 네트워크 구조 (Policy/Value + 관측 인코더)

- **관측 인코더(`network/encoder=lq`)**: Perceiver 계열 Latent-Query Attention 인코더
  - `encoder_depth=4`, `num_latents=16`, `dk=64`, `latent_num_heads=2`, `cross_num_heads=2`, `ff_mult=2`, `tie_layer_weights=true`
  - 입력: 주변 객체(최근접 8개, `waypoints/velocity/yaw/size/valid`), 도로그래프(top-k 200, `element_types=[15,16]`, 70m 전방/5m 후방/20m 좌우 박스), 신호등(최근접 5개), 경로 타깃(1점) — 벡터화 관측(`observation_type=vec`)
- **Policy Head**: MLP `[256, 256]`, ReLU, Gaussian action distribution
- **Value Head**: MLP `[256, 256]`, ReLU→ReLU, `num_networks=2`(Double-Q), `shared_encoder=false`
- **알고리즘**: SAC — `learning_rate=3e-4`, `discount=0.99`, `tau=0.005`, `alpha=0.2`(고정, auto-tune 미사용), `grad_updates_per_step=4`

### 2.3 연산량/자원 제약 대응 (FLOPs·Cut-off 관점)

- 대회 Motion Planning 1차 평가(Cut-off) 기준: PDM 알고리즘 처리시간(0.028초/시나리오, RTX4090 batch64)의 1.5배 초과 시 탈락
- **현재 미측정 항목**: 본 실험은 GTX 1660(6GB)에서 수행되어 RTX 4090 기준 Cut-off 배율을 직접 비교할 수 없음. 평가 스크립트 실측 처리량은 896 episode를 99.57초에 처리(평균 0.111초/episode, batch_size=4)했으나, 이는 공식 T_infer 정의(순수 추론 시간)와 동일한 측정 방법론이 아니므로 **그대로 인용 불가** — RTX 4090 환경 재측정이 6장 액션아이템에 반영됨
- 메모리 제약 대응: 기본 설정(`num_envs=16`) 사용 시 시스템 RAM(15GB) 초과로 OOM(exit code 137) 발생을 실측 확인 → `num_envs=4`로 축소하여 피크 RAM 12.8GB 수준으로 안정화(2.2절 상세는 5.3절 참조)

### 3.2 도메인 적응 관련 핵심 판단

- 대회 공식 미래궤적예측(Motion Prediction) test set(`test_public.tar.gz`, 4,324 시나리오)을 직접 확인한 결과 **hanam 2,359 / jeju 1,965 / livinglab 0** 구성으로, livinglab(KATRI 폐쇄시험장) 도메인이 test에 전혀 포함되지 않음을 확인함
- 이에 따라 **livinglab 데이터를 학습셋에서 제외**하고 hanam·jeju(실도로) 데이터에 집중하는 전략을 채택함 (본 실험은 이 중 jeju 확보분만으로 1차 실행)
- **한계**: 본 실험의 평가는 jeju 학습셋에서 무작위 샘플링한 300개 시나리오(`val_sample_shards`, seed=42)를 사용했으며, 이는 **학습에 이미 사용된 데이터와 동일 풀에서 추출한 것으로 진성 held-out 검증이 아님**. 현재 수치는 과적합 여부를 배제하지 못하는 낙관적 추정치로 해석해야 함

### 3.3 변환 파이프라인 검증 (Waymo Open Dataset 포맷 정합성)

- 원본 TFRecord 스키마를 직접 파싱하여 `state/past|current|future`(150/1/150 step), `roadgraph_samples/*`, `traffic_light_state/*`, `scenario/id` 등 79개 feature가 Waymo Open Motion Dataset(WOMD) 표준 스키마와 100% 일치함을 확인함
- `make_91f.py` 변환 결과 23,753/23,753 파일 성공(실패 0), `make_waymax_shards.py` 샤딩 후 Waymax `simulator_state_generator`로 실제 로드하여 `log_trajectory.shape == (1, 128, 91)`(과거10+현재1+미래80)을 직접 확인함 — 데이터 파이프라인의 구조적 정합성을 실증적으로 검증함

## 4. AI 모델 설계 및 핵심 제어 알고리즘 (Model & Strategy)

### 4.1 보상 함수 설계 (Safe RL 관점)

```
reward_config:
  overlap: -1.0              # 충돌 페널티 — ScenarioScore의 no_collision 항과 직결
  offroad_in_box: -1.0        # 방향 무관 도로이탈 페널티(라이드플럭스 챌린지 전용 정의) — on_road 항과 직결
  expert_progression: 10.0    # 전문가 경로 대비 진행도 보상 — progress 항과 직결
termination_keys: [offroad_in_box, overlap]
```

- 대회 채점식 `ScenarioScore = no_collision × on_road × (7·progress + 3·comfort) / 10`의 **치명적 실수 항목(충돌/이탈)을 termination_keys로 직접 하드 페널티화**하고, 진행도(progress)에 가장 큰 보상 가중치(10.0)를 부여하여 채점식의 progress 가중치(7/10)와 방향을 일치시킴
- `comfort` 항은 이번 1차 실험의 `reward_config`에는 명시적으로 포함하지 않음(기본값 미사용) — 평가 지표상 `comfort: 0.60079`가 별도로 산출되고 있으나 보상에 직접 반영되지 않아, 다음 단계에서 `comfort` 보상항 추가 여부를 검토할 필요가 있음(6장 액션아이템)

### 4.2 하이퍼파라미터 및 학습 안정성

| 항목 | 값 | 비고 |
|---|---|---|
| Algorithm | SAC | 베이스라인 기본값 |
| learning_rate | 3e-4 | 베이스라인 기본값(변경 없음) |
| discount(γ) | 0.99 | |
| tau | 0.005 | target network soft update |
| alpha | 0.2 (고정) | entropy coefficient, auto-tune 미적용 |
| batch_size | 64 | |
| grad_updates_per_step | 4 | |
| buffer_size | 20,000 | 베이스라인 기본값(100,000) 대비 축소 — RAM 제약 대응 |
| learning_start | 2,000 | |
| num_envs | 4 | 베이스라인 기본값(16) 대비 1/4 축소 — **RAM 제약 대응(핵심 변경점)** |
| total_timesteps | 200,000 | 베이스라인 권장(25,000,000) 대비 0.8% 규모 — **1차 검증 목적** |

- Warm-up 전략: `learning_start=2000` 스텝까지 리플레이 버퍼를 사전 채운(prefill) 후 학습 시작 — 학습 초기 불안정한 정책으로 인한 편향된 경험 축적을 방지

### 4.3 관측/맵 표현

- 벡터화 관측(vec) 사용: 원시 포인트클라우드형 도로그래프(30,000점) 대신 top-k 200점으로 축약, 차량 기준 전방70m/후방5m/좌우20m 박스 필터링으로 연산량 절감
- 최근접 객체 8개, 신호등 5개로 제한 — 6GB급 GPU에서도 관측 인코딩 연산량이 감당 가능한 수준으로 조정됨

### 5.4 위험 상황(Edge Case) 분석

- 본 1차 실험 범위에서는 시나리오 유형별(급차선변경, 센서노이즈 등) 세분화 분석을 수행하지 않음 — `evaluation_episodes.csv`(896행, 시나리오별 원자료)가 확보되어 있어 후속 분석(예: `offroad_in_box=1`인 실패 케이스만 필터링해 원인 분석)이 가능한 상태이며, 이는 6장 액션아이템으로 이관함

## 6. 재현성 검증 및 제출 준비 (Reproducibility & Code Deliverables)

### 6.1 재현성 확보 현황

- **환경**: `uv sync`로 고정된 `uv.lock` 기반 — JAX(CUDA13 wheel), Waymax(`waymo-research/waymax` 특정 커밋 고정), tensorflow-cpu 등 전체 의존성 버전 고정
- **하이퍼파라미터**: Hydra `.hydra/overrides.yaml` / `.hydra/config.yaml`에 실행 시점 전체 설정이 자동 저장되어 있어 100% 재현 가능
