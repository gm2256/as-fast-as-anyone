## 2. 터미널에서 학습(Training) 실행하기

모든 학습은 **`V-Max/` 디렉터리에서** 실행합니다.

### 2.1 기본 SAC 학습 (단일 데이터셋)

```bash
cd V-Max
CUDA_VISIBLE_DEVICES=0 uv run vmax/scripts/training/train.py \
    algorithm=sac network/encoder=lq \
    total_timesteps=200000 num_envs=4 num_episode_per_epoch=1 \
    algorithm.buffer_size=20000 algorithm.learning_start=2000 \
    waymo_dataset=true \
    path_dataset=/home/ehdtod001009/vmax_workdir/data/shards/full/full.tfrecord@58925 \
    name_run=my_run_name log_freq=50 save_freq=5000
```

- `path_dataset`: `data/shards/full`(전체 통합), `data/shards/hardcase`/`random_control`(A/B 실험용) 등 원하는 샤드 경로 사용
- **주의**: 로컬 GPU가 GTX 1660(6GB), 시스템 RAM 15GB뿐이라 `num_envs`를 함부로 올리면(예: 16) RAM이 넘쳐 OOM 발생함 — `num_envs=4`가 실측으로 안전한 값

### 2.2 다른 run의 가중치로 이어학습 (warm-start)

```bash
    algorithm.pretrained_params_path=runs/jeju_run1/model/model_final.pkl \
```
- **정책 가중치만** 이어받음 (옵티마이저·리플레이버퍼는 새로 시작). 네트워크 구조(encoder, layer_sizes)가 동일해야 함(shape mismatch 시 에러).
- 경로에 한글(예: `대회`)이 섞인 절대경로를 쓰면 Hydra 파서가 깨짐(`LexerNoViableAltException`) — **반드시 `V-Max/` 기준 상대경로**로 쓸 것.

### 2.3 여러 풀을 가중치로 섞어서 학습 (mixture_datasets)

hard/easy, 제주/한남 등 여러 풀을 원하는 비율로 섞어서 학습할 때 사용. **전체 데이터를 그대로 두고 "얼마나 자주 뽑히는지"만 조절**하는 방식(데이터를 줄이는 것보다 이게 낫다는 게 실험으로 확인됨).

```bash
CUDA_VISIBLE_DEVICES=0 uv run vmax/scripts/training/train.py \
    algorithm=bc network/encoder=lq \
    total_timesteps=200000 num_envs=4 num_episode_per_epoch=1 \
    algorithm.buffer_size=20000 \
    waymo_dataset=true \
    'mixture_datasets=[{path: /home/ehdtod001009/vmax_workdir/data/shards/bc_pools/hard/hard.tfrecord@23570, weight: 0.3}, {path: /home/ehdtod001009/vmax_workdir/data/shards/bc_pools/easy/easy.tfrecord@35355, weight: 0.7}]' \
    name_run=my_bc_run log_freq=50 save_freq=5000
```

- **⚠️ 메모리 주의**: 풀 하나당 데이터 파이프라인이 하나씩 떠서 메모리를 먹습니다. 이 기계(RAM 15GB) 기준 **풀 4개 동시 사용 시 OOM으로 프로세스가 죽는 것을 실측 확인**했습니다. **2개 풀까지만 안전** — 그 이상 세분화하고 싶으면 `merge_pools.py`로 미리 합쳐서 풀 개수를 줄일 것.
- BC(`algorithm=bc`)는 기본 `buffer_size=1,000,000`이라 그대로 쓰면 **GPU(6GB) OOM**남 — 반드시 `algorithm.buffer_size=20000` 같은 값으로 줄일 것.
- `algorithm=bc_sac`(BC+SAC 하이브리드)도 사용 가능하나, 이 세션에서는 `pretrained_params_path`/`resume`를 아직 지원하도록 패치하지 않음.

### 2.4 각 알고리즘별 참고

| algorithm | 용도 | policy 출력 | 기본 buffer_size |
|---|---|---|---|
| `sac` | 순수 RL | 가우시안 분포 파라미터(4차원) | 100,000 (jeju/hanam_run1은 20,000으로 축소해서 씀) |
| `bc` | 모방학습(사전학습용) | 행동 직접 출력(2차원, tanh) | 1,000,000 (**반드시 줄일 것**) |
| `bc_sac` | BC+SAC 하이브리드 | 가우시안(SAC와 동일 구조) | 500,000 |

⚠️ `bc`와 `sac`는 policy 네트워크 출력 형태가 달라서 **`bc`로 학습한 가중치를 `sac`의 `pretrained_params_path`에 바로 못 씀** (shape mismatch). BC→RL로 이어가려면 `bc_sac`를 쓸 것.

## 3. 체크포인트 (저장 / 재개)

### 3.1 저장 위치
`runs/<name_run>/model/`에 저장됩니다.
- `model_<step>.pkl`, `model_final.pkl`: 정책(및 SAC는 가치망) 파라미터만
- `train_state_latest.pkl`: **옵티마이저 상태 + 스텝 카운터까지 포함한 전체 상태** (SAC만 지원, 매 `save_freq`마다 갱신)

### 3.2 자동 재개 (resume)
`algorithm.resume=true`가 기본값입니다. **같은 `name_run`으로 같은 명령을 재실행**하면, `train_state_latest.pkl`이 있을 경우 자동으로 그 지점(env_steps)부터 이어서 학습합니다(`total_timesteps`는 절대 목표치로 취급됨).

```bash
# 컴퓨터가 중간에 꺼졌거나 멈췄을 때: 완전히 똑같은 명령을 그대로 재실행하면 됨
uv run vmax/scripts/training/train.py algorithm=sac ... name_run=hanam_run1 ...
```

강제로 처음부터 다시 하고 싶으면 `algorithm.resume=false` 추가.

**실전 검증됨**: 학습 도중 컴퓨터가 예기치 않게 재부팅된 적이 여러 번 있었는데, 그때마다 동일 명령 재실행으로 정확히 중단 지점부터 재개되는 것을 실측 확인함.

## 4. 평가(Evaluation) 실행하기

### 4.1 V-Max 자체 평가 (내부 검증용)

```bash
cd V-Max
CUDA_VISIBLE_DEVICES=0 uv run python vmax/scripts/evaluate/evaluate.py \
    --waymo_dataset=true \
    --path_dataset=/home/ehdtod001009/vmax_workdir/data/eval/val_sample_shards_hanam/val_sample_shards_hanam.tfrecord@300 \
    --sdc_actor=ai \
    --path_model=hanam_run1 \
    --batch_size=4
```
- `--path_model`은 `runs/` 아래 폴더 이름 (자동으로 그 안의 `model_final.pkl` 사용)
- 결과: `results/<path_model>/evaluation_results.txt`, `evaluation_episodes.csv`
- **모든 모델은 항상 `data/eval/val_sample_shards_hanam`(고정 300개, seed=42) 하나로만 비교** — 다른 샘플 쓰면 점수 비교 불가

### 4.2 대회 공식 채점 프로그램으로 평가

```bash
cd dxchallenge_planning_eval
CUDA_VISIBLE_DEVICES=0 uv run evaluate.py \
    --path_dataset /home/ehdtod001009/vmax_workdir/data/eval/val_sample_shards_hanam/val_sample_shards_hanam.tfrecord@300 \
    --submission submission_hanam_run1
```
- 결과: `results/submission_hanam_run1/evaluation_results.txt` (rideflux_score 등)
- V-Max 자체 평가와 **완전히 독립된 코드**인데 점수가 거의 일치(0.5375 vs 0.5325)하는 것으로 교차검증 완료됨

### 4.3 새 모델을 제출물로 포장하기

1. `export_policy_weights.py`로 가중치 추출:
   ```bash
   cd V-Max
   uv run python scripts/export_policy_weights.py runs/<name_run>/model/model_final.pkl \
       ../dxchallenge_planning_eval/submission_<name_run>/weights.pkl
   ```
2. `dxchallenge_planning_eval/submission_hanam_run1/`의 `actor.py`/`feature_extractor.py`/`network.py`를 복사해서, 그 실행의 `runs/<name_run>/.hydra/config.yaml`에 적힌 실제 `observation_config`/`network` 설정에 맞게 값만 고치기 (예: `num_closest_objects`, policy `layer_sizes`)
